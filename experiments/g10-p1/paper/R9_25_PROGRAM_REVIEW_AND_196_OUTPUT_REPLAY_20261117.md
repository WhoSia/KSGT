## 초기 196건의 응답 행 단위 재현

Drive에서 초기 원본 ZIP 11개를 다시 받았다. ZIP CRC, ZIP과 raw JSON SHA-256, 원본의 응답 행 번호, 글감·모델·조건, 기록된 프롬프트 SHA-256, 생성문 문자열 SHA-256을 대조 원장에 남겼다. 아래 프롬프트 해시는 ZIP에 기록된 값을 비교했다.

| 원본 실행 | 완료 | 실패 |
| --- | ---: | ---: |
| Pilot 001 | 0 | 5 |
| Pilot 002 / 003 / 004 / 005 | 5 / 15 / 15 / 15 | 0 |
| Factorial 001 / 002 | 24 / 36 | 0 |
| Qwen Family Smoke | 5 | 0 |
| CrossFam 001 / 002 | 27 / 27 | 0 |
| RawSource 001 | 27 | 0 |
| 합계 | 196 | 5 |

- 196건 모두 기록상 Groq 응답 종료 사유가 `stop`이고 본문이 있다. 20B 72건, 120B 92건, Qwen 27B 32건이다. Pilot 001의 404 실패 5건은 별도 보존했다.
- 기록된 글감 ID는 6개다. 프롬프트 해시 57개, 모델–프롬프트 해시 쌍 125개, 완전히 같은 출력 문자열을 합친 수는 188개다. 글감 ID의 개수는 독립 저작물의 개수로 쓰지 않는다.
- 빈 줄 기준으로는 186건이 한 문단, 3건이 두 문단, 6건이 세 문단, 1건이 여섯 문단이다. 역사 기록의 ‘196개 단일 문단’ 명칭은 문단 생성 코호트를 가리킨다. 빈 줄은 기계적인 형식 기준이다.
- CrossFam 001/002는 동일 글감·모델·조건 27쌍에서 기록된 프롬프트 해시가 27/27 일치했다. 응답 문자열 SHA-256 일치는 2/27이다. 두 실행 사이의 모델 서버 상태나 변동 원인을 분리할 수 없다.
- 대표 문장 대조에서도 출력 선택이 달랐다. 과학 설명은 같은 역할 계획에서 미측정 사실로 끝난 실행과 원인 미확인까지 다시 밝힌 실행이 갈렸다. 장면은 두 실행 모두 포스터에서 우산 장면으로 옮겨 갔다가 끝에서 포스터로 돌아왔고, 한 번만 비 때문에 우산을 건넸다는 인과 연결을 썼다. 안내는 한 실행에서 준비물이 필요 없다고 한 뒤 노트북 필요 여부가 미정이라고 썼다. 이 세 사례는 수작업 점검이며 빈도를 추정하지 않는다.
- R5–R8 4개 ZIP과 전역 36편 ZIP도 다시 받았다. 다섯 ZIP의 SHA-256은 R9.23 장부와 일치했고, 9+18+18+18=63과 36 원문을 다시 읽어 집계했다. 이렇게 역사 시점 295건의 각 집계 범주를 실제 아카이브에 연결했다. R9.14 및 R9.23의 후속 출력은 별도 실행이다.

## 새 교정 비교와 연구 우선순위

세 조건에서 R9.23의 정확한 초안, 전체 원천, 기본 교정 프롬프트, 동일 모델·온도·출력 설정을 공유한다. 일반 교정과 평문 교정 사이에는 편집 정보 유무의 효과가, 평문과 구조화 지시 사이에는 동일한 다섯 요소를 표현하는 방식의 효과가 들어 있다. 같은 편집 지시라도 코드의 문자열과 JSON 객체가 모델에 제시되는 방식과 토큰 수는 다를 수 있다.

| 조건 | 추가로 전달하는 정보 |
| --- | --- |
| 일반 | 공통 프롬프트만 |
| 평문 | 기존 편집 지시의 유형·구절·근거·독자 영향·수정 제안을 문장으로 표현 |
| 구조화 | 같은 다섯 요소를 JSON 필드로 제공 |

실제 초안 3편으로 9개 입력을 만들었다. 각 조건이 첫째·둘째·셋째 위치에 한 번씩 배치된다. 기존 6개 계획은 출력 바이트 전체가 R9.24와 일치했다. 구조화 조건의 user 메시지는 평문보다 55–73자가 많았지만 UTF-8로는 37–72바이트 작았다. 실제 토큰은 공급자 사용량으로 확인해야 한다. Node 12/12, Python 5/5 로컬 테스트 통과. 새 Groq 호출과 독자 평가는 0건이다.

다음 비교는 먼저 세 개발 글감에서 각 조건을 한 번 돌려 누락·문단 수·공급자 영수증을 점검한 뒤 반복 실행을 남긴다. 결과를 읽을 때는 과학 글의 인과 강도, 공지의 독자 행동, 장면의 행위자와 상대를 각각 확인한다. 원천에서 모르는 내용이 추가됐는지, 핵심 정보가 빠졌는지, 글 전체가 매끄러운지 따로 기록한다. 같은 수정 정보를 주고도 구조화 방식에서 일관된 개선이 없으면, 복잡한 표현 형식을 더 만드는 작업의 우선순위를 낮춘다.

그다음 이미 사용한 글감과 분리한 새 원천에서 교정이 필요한 사례와 초안이 충분히 좋은 사례를 함께 시험한다. 새 원천에서는 강한 직접 생성도 비교에 포함하고, 형식과 교정 정보의 효과를 확인한 뒤에만 경량 계획을 초안 작성 단계로 옮겨 테스트한다. 개인 서버의 가치가 큰 일은 출처와 분할 확인이고, 소수의 짝지은 생성과 비용 영수증에는 기존 Groq 실행 경로가 적절하다.

```bash
python3 experiments/g10-p1/r925_replay_paragraph_archives.py PRIVATE_ARCHIVE_DIR
node --test experiments/g10-p1/r924_anchored_revision_v01.test.cjs
node experiments/g10-p1/r924_anchored_revision_v01.cjs --dry-run-three r923_complete.json r924_anchored_notes.json
node experiments/g10-p1/r924_anchored_revision_v01.cjs --execute-three r923_complete.json r924_anchored_notes.json NEW_OUTPUT_DIR
```
