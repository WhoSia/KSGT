# R6s — Task-conditioned whole-text writing: structured planning versus draft revision

R6r mandatory patch negative; this trial compares planning before writing to writing before revising. Four new investigator-authored synthetic briefs, no archived or corpus text sent. Each brief has identical genre, audience, intended effect, paragraph count and numbered source facts. Strong common instruction in all calls. Two arms with two calls each: DIRECT draft then REVISE (full text), PLAN then REALIZE (full text). First DIRECT draft is also the one-call baseline. Same GPT-OSS120B, temperature 0, maximum 1600 tokens per call; alternate arm order by brief. Not equal actual token usage. PLAN outputs a finite fact partition, paragraph role, focus and rhythm from fixed vocabulary; local validation requires each fact ID exactly once and correct paragraph count, no additional fields. Invalid plan is recorded and realization uses only original source with the same realization instruction, no repair/retry. This is an interface contract, not semantic validity. REALIZE gets same source plus derived plan; REVISE gets same source plus derived draft. Both free to write naturally. No hand-authored per-work preferred order supplied, no hard temporal gate: writing order and event order differ. No provider calls beyond 16, stop on provider failure, preserve all receipts, dynamic parent text hash and exact prompts replayed. Review complete texts for source fact omissions/additions, audience/register, paragraph progression, literary effect; descriptive investigator reading only, no human preference claim. Compare actual tokens and latency, including both stages. Record negative result, no selective retry. No independent human evidence, no training. Keep architecture open.
