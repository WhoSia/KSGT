# R7h branch-conditioned continuation pilot
Four fresh investigator-written complete-prefix tasks, two author-defined worlds per task. OPEN leaves a motive/interpretation unresolved or explicitly communicates a currently unresolved practical fact; RESOLVED supplies a distinct fact or intention. Identical fixed prefix and common facts per work. Output is a finished continuation, not a survey response. SEPARATE calls one per branch (8 calls, max completion 1800 each). JOINT sees both branch descriptions once and outputs both separate continuations (4 calls, max completion 3600 each). Each call requests a strict JSON object with only required branch keys, values Korean prose strings, no repeated prefix. Shared system instructions, genre, task and common facts. Not identical input: joint context explicitly includes other branch. Alternate schedule order across works. Same GPT-OSS120B temp0. Compare 8 separate vs 4 joint calls with 8 complete texts per method, token/latency and actual text inspection. Primary focal author-constraint check: do the two continuations preserve the author-specified difference without cross-branch leakage? Secondary common facts, terminal behavior, excess exposition, novel unsupported assertions and expressive differences. No independent quality gold; no population preference, no questionnaire or new human recruitment. Investigator-written briefs, not natural data or training. Joint budget doubles per call; equal maximum aggregate output tokens per work, not actual cost parity. Provider errors/truncation stop and preserve receipts; no silent retry. No automatic architecture adoption. Contrast R6z candidate-aware one text per call and R7f source projection: here shared-prefix alternative world generation is the intervention, not a heading rearrangement.
