# Proposed P62 referential-grounding infrastructure

P62 remains a bounded proposed-stage execution. CURRENT_STAGE stays P60, P59/P60 remain open, and Draft PR #1 must not be merged without authorization.

The private corpus pipeline is deliberately distinct from semantic validation. All generated independent-human-ground-truth fields remain null. No licensed text, private identifiers, annotation packets, review HTML, databases or result receipts belong in GitHub.

## Execution and identity

p62_execute.py requires the private DIRECTIONAL_ESTIMAND_PREDECLARATION and EXECUTION_LOCK, frozen P61 source SQLite, P61 private artifacts, and a new private output directory. It checks exact input/code SHA-256, audits repeated source keys without weak-title merging, preserves component membership, scans every frozen paragraph shard, and commits per-shard metrics/checkpoints atomically. A bounded committed stop can resume; this does not certify power-loss durability. Work keys frame sorted component membership; membership changes create a new snapshot identity. Observed split disjointness is not global work independence.

p62_reference.py supplies Unicode source spans, separate machine proposals, strict source grouping, symmetric windows and document-equal component bootstrap. Numeric groups, topic/argument fragments, enumeration fragments and event predicates remain proposals. An inferred omitted argument has no observed span and needs separate evidence and uncertainty. Future candidates are predictive controls; ordinary antecedents cannot be admitted from them merely because words match.

The primary future human estimand compares structural and lexical top-1 span alignment, with an IoU threshold of 0.5 against admitted antecedent spans. It remains unexecuted without qualified independent evidence. Repeated window views must collapse to unique source-structure/target spans before document means.

## Private review workflow

p62_review.py builds A/B local HTML batches with independently randomized item/candidate order, Unicode-safe offsets and at most six displayed candidates per temporal relation. Full proposal inventories and source context remain in the private packet; reviewers can add manual spans. Machine predictions and release labels are hidden. Chronology is visible, so this is prediction-blind presentation, not certified double-blind validation. Export ledgers frequently.

Use p62_annotation.py for response import and evaluation, with a separate qualification/independence registry supported by actual evidence. Self-attestation is insufficient. Original responses are never overwritten. Conflicts remain unresolved until separate adjudication. The low-level reference module is not an independent-human admission interface. Reliability uses only actually verified reviewer responses; absent evidence returns null/HOLD. No packet ground truth is automatically promoted.

## Falsification and claim ceilings

p62_particle.py is a separately sealed right-boundary sensitivity. p62_counterfactual.py excludes only the post-target quantity used to define compatibility from future feature evidence. Neither changes source prose. Original strict outcomes remain preserved.

The executed private diagnostics show substantial measurement dependence: inter-only group direction remains uncertain; intra-unit feature choices can reverse compatible-counter direction; removing the defining quantity flips it again. Unrelated numeric repetition and metalinguistic mention produce synthetic proxy counterexamples. These falsify proxy sufficiency, not Korean reference itself. Particle-aware matching expands rule coverage, not validated antecedent recall.

Source-family, actual-year, length and retrospective split views are exploratory. No generation benefit, human preference, causal effect or referential accuracy follows from these counts.
